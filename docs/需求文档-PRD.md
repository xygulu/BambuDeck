# BambuDeck 需求文档(PRD)

- 版本:v0.1(草案)
- 日期:2026-10-15
- 前身项目:BambuHelper v3.9.0(ESP32 拓竹打印机监控固件,位于 `../BambuHelper`,**保持不动,仅作协议与需求参考**)
- 项目代号:BambuDeck(可改名)

---

## 1. 项目背景与定位

### 1.1 背景

BambuHelper 是一个成熟的 ESP32 固件:通过 MQTT over TLS 连接拓竹打印机,在 1.28"~3.5" 的 TFT 小屏上渲染仪表盘(进度弧、温度仪表、AMS 耗材、HMS 错误、智能插座功耗等),并带一个设备端 Web 配置门户。它的能力边界由硬件决定:

- 屏幕小,单屏只承载"一台打印机"的状态;
- 无视频解码能力(仅 P1/A1 机型的 MJPEG 缩略图级画面),无法承载真正的摄像头监控;
- 交互靠触摸/单按键,信息密度与多任务视图受限。

### 1.2 新项目定位

BambuDeck = **打印机监控 + 摄像头监控**的多平台融合监控台:

1. **监控画面升级**:同一画面内既有打印机状态(进度/温度/耗材/错误),又有多路实时摄像头视频(小米、萤石、海康/大华等第三方通用摄像头、以及拓竹打印机自带相机),面向**桌面大屏、平板、电视挂屏、手机**等场景;
2. **两种使用形态**:
   - **独立客户端模式**(Standalone):App 直连打印机和摄像头,零服务端;
   - **服务端 + 客户端模式**(Hub):常驻服务聚合多打印机/多摄像头、转发低延迟视频流,支持多客户端与远程访问;
3. **五端覆盖**:Windows、macOS、Linux、Android、iOS。

### 1.3 目标用户与核心场景

| 场景 | 说明 |
|---|---|
| 桌面副屏常显 | 打印机状态 + 打印腔摄像头同屏,打印失败/HMS 错误即时可见 |
| 平板/电视大屏挂墙 | 多打印机 + 多摄像头网格布局,kiosk 全屏轮播 |
| 手机随行 | 出门在外看进度、看家里监控画面,收完成/失败推送 |
| 打印房管理 | 一台 Hub 聚合多台打印机与多路摄像头,PC/手机同时查看 |

### 1.4 与原项目的关系

| 维度 | BambuHelper(ESP32) | BambuDeck(本项目) |
|---|---|---|
| 载体 | ESP32 + TFT 小屏 | Win/mac/Linux/Android/iOS App + 可选 Hub 服务 |
| 打印机数据 | MQTT(局域网/云)双模式 | **继承同一协议**,双模式保留 |
| 打印机控制 | 只读 + 腔灯 + 插座断电 | 扩展:暂停/恢复/停止/速度/腔灯(见 FR-2) |
| 摄像头 | P1/A1 MJPEG 缩略图 | 多品牌多路实时视频(核心新能力) |
| 功耗 | Tasmota/Shelly/Kasa 插座 | 继承,交互增强 |
| 多打印机 | 最多 4 台 | 数量上限由硬件性能决定(建议 8+) |
| 提醒 | 蜂鸣器/LED | 系统通知/常驻通知/推送(经 Hub) |

## 2. 总体架构

### 2.1 两种运行模式

```
模式 A:独立客户端(Standalone)
┌─────────────────────────────┐
│  BambuDeck App(任意平台)     │
│  ├─ MQTT 客户端 ─────────────┼──► 打印机(局域网 MQTT 8883 / Bambu 云 MQTT)
│  ├─ RTSP/ONVIF 客户端 ───────┼──► 摄像头(RTSP 直拉)
│  └─ 插座 HTTP 客户端 ────────┼──► 智能插座(Tasmota/Shelly/Kasa)
└─────────────────────────────┘

模式 B:服务端 + 客户端(Hub)
┌──────────────┐   WebSocket/HTTP    ┌──────────────────────────────┐
│ BambuDeck App │ ◄────────────────► │ BambuDeck Hub(常驻服务)       │
│ (手机/PC/平板) │   视频:WebRTC/HLS  │  ├─ 多打印机 MQTT 聚合          │
└──────────────┘                     │  ├─ 多摄像头接入(RTSP/ONVIF)    │
                                     │  ├─ (可选)go2rtc 流媒体引擎     │
                                     │  └─ 鉴权 / 多客户端 / 推送        │
                                     └───┬─────────┬─────────┬───────┘
                                         ▼         ▼         ▼
                                       打印机×N   摄像头×N   插座×N
```

**两种模式的关系**:同一套 App 代码,内置"直连"与"连接 Hub"两种数据源;Hub 是可选组件,不装 Hub 时 App 独立工作,装了 Hub 获得聚合/远程/推送能力。

### 2.2 模式能力对比

| 能力 | 独立客户端 | Hub 模式 |
|---|---|---|
| 打印机监控(局域网/云) | ✅ 直连 | ✅ 由 Hub 代理 |
| 摄像头 RTSP 直拉 | ✅ 需客户端与摄像头同网(或路由可达) | ✅ 由 Hub 拉流后转发 |
| 低延迟视频(WebRTC) | ⚠️ 受平台播放器限制(见 4.3) | ✅ go2rtc 统一转 WebRTC |
| 多客户端同时看 | 各自直连(打印机 MQTT 连接数增多) | ✅ 一份上游连接,N 个客户端 |
| 外网/异地访问 | ❌ 不提供 | ✅ Hub 鉴权后访问(自备穿透/VPN) |
| 离线推送(Android/iOS) | ❌ | ✅ 经 Hub(ntfy/FCM/APNs,见 FR-7) |
| 视频 Web 端(浏览器) | ❌ RTSP 无法进浏览器 | ✅ WebRTC/HLS |

## 3. 名词表

| 名词 | 含义 |
|---|---|
| AMS | 拓竹自动供料系统,最多 6 单元 × 4 料槽 |
| HMS | 拓竹打印机错误码体系(HMS_xxxx-xxxx),附官方措辞与严重度 |
| LAN 模式 | 打印机开启局域网访问,以 IP + 访问码(access code,用户名 `bblp`)直连 MQTT |
| 云模式 | 经 Bambu 区域云 MQTT(`us/eu/cn.mqtt.bambulab.com:8883`,Bearer token)连接 |
| RTSP/ONVIF | 摄像头行业标准流媒体协议 / 设备发现与控制协议 |
| 萤石 EZVIZ | 海康威视旗下消费摄像头品牌,支持 App 内开启局域网 RTSP,另有萤石开放平台云 API |
| go2rtc | 开源多协议流媒体引擎(RTSP/RTMP/HLS/WebRTC/HomeKit 互转,不转码直封装) |
| Hub | 本项目的常驻服务端进程 |

## 4. 功能需求(FR)

优先级:P0 = MVP 必须;P1 = 重要;P2 = 后续增强。

### FR-1 打印机监控(P0)

完整继承 BambuHelper 的状态模型(`bambu_state.h`),字段清单即验收口径:

**4.1.1 任务与进度**
- 打印状态机:IDLE / RUNNING / PAUSE / PREPARE / FINISH / FAILED / UNKNOWN,及自动切换动画;
- 进度百分比、剩余时间(分钟)、预计完成时间(结合时区/DST 计算);
- 子阶段标签(`stgCur`,约 60 种:调平、加热、换料、 calibration 系列等,中英双语映射);
- 任务名、任务 ID、打印板号(plate idx)、当前层 / 总层数;
- 切片耗材映射(printMap)、校准任务类型识别。

**4.1.2 温度与风扇**
- 喷嘴温度/目标温(双喷嘴机型 H2D/H2C 显示 L/R 两路);
- 热床温度/目标温、腔体温度;
- 6 路风扇百分比:散热风扇、辅助风扇 L/R、腔体风扇、排气风扇、热交换风扇。

**4.1.3 AMS 耗材系统**
- 每料槽:有无、颜色(RGB)、耗材类型(如 PLA Matte)、剩余百分比(-1 表示第三方料盘未知);
- 每单元:湿度等级(0–5)与原始 RH%、温度、烘干剩余/总时长;
- 外部料卷(vt_spool)显示;
- 烘干中状态的专门视图(倒计时)。

**4.1.4 设备状态与错误**
- WiFi 信号(RSSI)、打印机 IP、打印速度档位(1 静音 ~ 4 疯狂);
- 舱门开合状态、腔灯状态;
- **HMS 错误**:错误徽标、错误详情页(官方措辞 + 严重度 FATAL/SERIOUS/COMMON + 模块名),继承"连接时已存在的错误码不告警"的基线抑制策略;错误码句表随 App 数据文件分发(原项目 2675 行句表直接移植);
- 上次打印完成时间。

### FR-2 打印机控制(P1,超出原项目的新能力)

原项目刻意只读;新项目面向桌面/手机,应提供控制能力(命令走同一 MQTT `device/{serial}/request` 通道,参照 OpenBambuAPI 社区协议文档):

| 控制项 | 优先级 | 说明 |
|---|---|---|
| 暂停 / 恢复 / 停止打印 | P0 | 停止需二次确认 |
| 打印速度档位切换 | P1 | 静音/标准/运动/疯狂 |
| 腔灯开关 | P0 | 与原项目对齐 |
| 开始打印(从历史/切片文件) | P2 | 依赖云文件接口,后续评估 |
| 控制权限区分 | P0 | LAN 模式(开发者模式)与云模式的可用命令集合可能不同,UI 需按连接模式降级隐藏 |

### FR-3 摄像头监控(P0,核心新能力)

**4.3.1 摄像头接入矩阵**

| 来源 | 接入方式 | 优先级 | 备注 |
|---|---|---|---|
| 通用 RTSP 摄像头(海康/大华/TP-Link/UNV 等) | 手工填 RTSP URL | P0 | 最大公约数,所有品牌兜底 |
| ONVIF 设备 |局域网 WS-Discovery 自动发现 + GetStreamUri + Profile/PTZ 控制 | P0 | `easy_onvif` 包 |
| 拓竹打印机自带相机(X1/P1/A1/H2 等) | LAN:`rtsps://<ip>/streaming/live`(用户 bblp/访问码);P1/A1 兼容 6000 端口 TLS MJPEG | P0 | 需打印机开启"LAN Mode Liveview";P1/A1 的 MJPEG 客户端逻辑可从原项目 `camera_client.cpp` 移植 |
| 萤石(EZVIZ) | ① App 内开启"局域网直连 RTSP"后按通用 RTSP 接入(**推荐,免费本地**);② 萤石开放平台云 API(AppKey/Secret → accessToken → `v2/live/address` 取流,ezopen/HLS/RTMP) | P1 | 云 API 有取流频控与有效期限制;文档见 open.ys7.com/help/1414 |
| 小米/米家摄像头 | ① 新型米家 App → 摄像头设置 → 网络信息开启 RTSP(**推荐**);② 老型号经 Micam 桥接服务转推 RTSP(非官方) | P1 | 米家官方不开放 ONVIF;Micam 为社区方案,文档标注风险 |
| 其他第三方 | 一律落到 RTSP URL 兜底;Hub 模式可挂 go2rtc 兼容更多协议(RTMP/HomeKit 等) | P1 | |

**4.3.2 视频播放要求**

- 播放引擎:Flutter `media_kit`(libmpv 内核)+ `fvp` 视图注册,五端覆盖;支持硬件解码;
- 低延迟直播调优:mpv low-latency 参数族(live 缓存、禁缓冲、快速 keyframe 恢复),目标直连 RTSP 端到端延迟 ≤ 2s;
- 已知风险与缓解:
  - **iOS 上 media_kit 的 RTSP 存在落后直播数十秒的缓冲问题** → ① 参数调优;② Hub 模式经 go2rtc 转 WebRTC(iOS 原生 WebRTC 延迟 < 1s,列为 iOS 推荐路径);③ 备选播放器 `flutter_vlc_player` 做 A/B;
  - **浏览器/Flutter Web 无 RTSP** → 仅 Hub 模式提供 Web 访问(WebRTC/HLS),独立模式不承诺 Web;
- 多路并发:单画面布局至少支持 4 路同时播放(桌面 1080p × 4 @ 硬解);超过时自动降帧/仅激活窗口解码(视口外暂停拉流);
- 单画面能力:截图(存相册/下载)、双击全屏、流断线自动重连与占位提示、多码流(主/子码流)切换。

**4.3.3 摄像头控制(P1)**
- ONVIF PTZ:方向、变倍、预置位调用;
- 萤石云 API(可选):PTZ 指令经开放平台转发;
- 截图与录像(P2:本地录像回放不在 MVP)。

### FR-4 组合监控画面(P0,核心差异化)

监控页面 = **打印机状态卡片 + 摄像头视频块**的自由组合布局,两套自适应形态:

**4.4.1 大屏/桌面形态(桌面端窗口 ≥ 1280 宽、平板横屏、电视)**
- 网格布局画布:预设模板(1+1、2+2、1 打印机 + 3 摄像头、4 打印机 + 4 摄像头……)+ 自由拖拽调整(块位置、行列跨度);
- 打印机块内含:进度弧/进度条、状态徽标、温度行、AMS 条、HMS 徽标、ETA——即原项目"卡片皮肤"的信息结构移植到响应式卡片;
- 摄像头块:实时视频,角标显示摄像头名与在线状态,异常时显示最后帧 + 断线原因;
- **Kiosk 全屏模式**:隐藏系统 UI、可设密码退出、多套布局定时轮播(如 30s 切换页面);
- 状态驱动视觉:打印中/完成/失败/HMS 用边框辉光与主题色高亮(继承原项目 edge-glow 语义)。

**4.4.2 手机形态(< 600 宽)**
- 底部导航:打印机 / 摄像头 / 全部(组合)/ 设置;
- 打印机详情页:进度大图 + 关键指标分组列表 + AMS 横滑 + HMS 卡片;
- 摄像头页:1 宫格沉浸播放 + 横滑切换摄像头,支持画中画(PiP)进入系统小窗(Android/iOS);
- "全部"页:状态卡片流(打印机卡在上、摄像头缩略流在下),点击进详情;
- 布局方案与大屏端共享(同一配置结构,手机端线性化呈现)。

**4.4.3 布局方案管理**
- 多套命名布局方案(如"打印房全景""单机特写""只看摄像头"),一键切换、Kiosk 轮播绑定方案序列;
- 布局方案可导入导出(JSON)。

### FR-5 智能插座与功耗(P1)

继承原项目 4 种插座协议,全部为局域网 HTTP/TCP:
- Tasmota(`/cm?cmnd=Status 10`)、Shelly Gen2/Gen3(`Switch.GetStatus`)、Shelly Power Strip Gen4(`Shelly.GetStatus` 多路计量)、TP-Link Kasa(KP115/HS110,TCP 9999);
- 功能:实时瓦数、今日/累计 kWh、**单次打印用电量**、电价与货币换算、打印结束后自动断电(延迟可配,热床未冷却时禁止断电的"热端闸门"继承,开门可取消)、插座远程开关(带确认);
- 交互增强(P1):功耗曲线图(按打印任务聚合,本地存储)、每打印机绑定插座;
- 小米/涂鸦插座接入列为 P2 调研项(原项目无此集成)。

### FR-6 多打印机管理(P1)

- 打印机数量上限:配置驱动,建议支持 ≥ 8 台(硬解与 MQTT 连接数允许时);
- 连接模式按台独立配置:局域网 / Bambu 云,云模式支持区域选择(US/EU/CN);
- 自动轮换:手动 / 自动循环 / "优先打印中"(继承原项目智能轮换语义);
- 组合视图:多打印机分屏(桌面)与状态卡流(手机);
- 局域网发现(P1):SSDP/mDNS 扫描发现打印机(原项目已有 SSDP 发现实现可移植)。

### FR-7 通知与提醒(P1)

| 通道 | 平台 | 优先级 |
|---|---|---|
| 系统本地通知 | 五端 | P0(应用前台/后台运行时) |
| Android 常驻通知栏(打印中显示进度) | Android | P1 |
| App 内声音/提示音(继承蜂鸣器事件语义:完成/失败/连接/HMS) | 五端 | P1 |
| **远程推送**(人不在局域网时) | Android/iOS | P1,依赖 Hub:优先对接 ntfy 自建推送(免开发者账号),FCM/APNs 列为 P2 |
| 通知规则 | — | P0:按事件类型(完成/失败/HMS/插座断电)与时段静音配置 |

### FR-8 云账号与配网(P0/P1)

- **Bambu 云登录**(P0):三种方式继承原项目——① 密码登录(可记住密码自动续期;遇 2FA 按原项目策略丢弃密码转验证码);② 邮箱 6 位验证码;③ 浏览器粘贴 access token;区域选择 CN/US/EU;账号下打印机列表选择;
- **局域网接入**(P0):IP + 访问码;局域网扫描发现(P1);
- **凭据安全**(P0):所有凭据(access code、云 token、摄像头密码、Hub 凭据)存 OS 安全存储(flutter_secure_storage → Windows Credential Manager / macOS Keychain / Linux libsecret / Android Keystore / iOS Keychain),禁止明文落盘;
- Hub 配置(P1):扫码/一次性配对码连接 Hub。

### FR-9 Hub 服务端(P1,模式 B)

- 形态:常驻进程,提供 Windows/macOS/Linux 原生二进制 + Docker 镜像(amd64/arm64,面向 NAS);
- 上游聚合:打印机 MQTT(局域网/云混合)、摄像头 RTSP/ONVIF、插座 HTTP;**上游连接数与客户端解耦**(1 份上游,N 客户端);
- 下游接口:
  - WebSocket API:状态推送(打印状态/插座/HMS 事件)、控制指令转发、配置管理;
  - 视频出口:WebRTC(首选,亚秒延迟)/ HLS(兼容兜底)/ RTSP 重推(供第三方如 Home Assistant 复用,P2);
  - 流媒体引擎:内嵌 go2rtc(独立进程 sidecar 或移植其核心),**不转码优先**(直接封装转发,CPU 占用低);
- 鉴权:用户名/密码 + token,TLS(自签证书引导生成);访客只读权限(P2);
- 事件推送:接 ntfy(P1)作离线推送通道;
- 资源目标:2 路 1080p 转封装 + 8 打印机聚合,CPU ≤ 20%(四核),内存 ≤ 512MB;
- 配置:Web 管理页(打印机/摄像头/用户/推送),配置导出导入。

### FR-10 设置中心(P0)

- App 设置:主题(深色默认/浅色/跟随系统)、强调色(继承原项目自定义 accent 能力)、语言(zh-CN / en,框架 i18n)、启动页(Kiosk 自启)、日志导出;
- 打印机设置:连接方式、仪表量程/颜色、控制权限开关;
- 摄像头设置:来源类型、地址/凭据、码流、名称与分组;
- 数据备份:全部设置 + 布局方案 JSON 导入导出(对应原项目设置导入导出能力)。

## 7. 边界与已知约束(需求层面的"不做"与"受限")

1. **不承诺**打印机固件对抗:拓竹固件升级可能收紧局域网/开发者模式(社区已知 2025 年 P 系 1.08 固件一度破坏开发者模式),文档中提供降级路径(切云模式);
2. **小米摄像头无官方 RTSP/ONVIF**:仅覆盖"新型号原生 RTSP + Micam 桥接"两条路径,Micam 属社区方案,风险随米家固件变化,文档明示;
3. **萤石云 API** 取流地址有有效期与频控,不作为常驻画面主路径(推荐用户开启局域网 RTSP);
4. **独立模式不做外网穿透**;远程能力统一由 Hub 承担(用户自备 VPN/端口转发/反代,文档给建议但不内置隧道服务);
5. 原项目 ESP32 固件**保持独立演进**,本项目不回写;二者可共存(同一个打印机允许多客户端订阅)。

## 8. 验收标准(关键场景)

| # | 场景 | 验收口径 |
|---|---|---|
| AC-1 | 局域网直连 | 输入打印机 IP + 访问码,≤ 5s 出全量状态;拔网线 30s 内出现离线态,恢复后 ≤ 10s 自动重连且数据完整 |
| AC-2 | 云模式 | 邮箱验证码登录 → 选择打印机 → 状态与局域网模式一致;token 过期自动续期无感 |
| AC-3 | 组合大屏 | 4 打印机 + 4 摄像头布局在 27" 1080p 下无滚动完整呈现;任一打印机 HMS 触发红色辉光 + 通知 |
| AC-4 | 摄像头矩阵 | 同一布局内同时稳定播放:1 台拓竹自带相机(RTSPS)+ 1 台萤石(局域网 RTSP)+ 1 台小米(原生 RTSP)+ 1 台海康(ONVIF 自动发现)≥ 30 分钟不崩、断流自动恢复 |
| AC-5 | 手机 | Android/iOS 手机单手完成:看进度 → 切摄像头 → PTZ 转动 → 收到完成推送 |
| AC-6 | Hub | 1 台 NAS 级设备聚合 4 打印机 + 2 摄像头,3 个客户端(手机×2 + 桌面×1)同时观看,视频延迟 WebRTC ≤ 1s,上游打印机 MQTT 连接数为 1 份 |
| AC-7 | 功耗 | 绑定 Tasmota 插座的打印机完成打印后,按配置延迟自动断电;热床 > 50°C 时不执行 |
| AC-8 | 五端 | 同一份布局方案 JSON 在 5 端导入后均可正常渲染(自适应降级) |
